# 权重标定：`foundation_loss_weight` 是怎么定下来的

> P0 用的 `0.05` 从未被论证。本文记录把权重定下来的过程：
> 早期扫描为什么给不出答案、为何改用梯度比，以及最终 VOC A/B/C/D 四格权重的依据。
>
> 全部证据在 [`../../results/`](../../results/)。

## 1. 要解决的问题

训练目标是

```
总损失 = 检测损失 + w × KD损失
```

`w` 太小等于没开，太大会抢走检测的学习。早期协议为此预注册了扫描与选取准则：

> 取使检测损失相对 `w=0` 基线不劣化（≤ 1.02×）的**最大**权重。

## 2. 扫描结果：准则给不出答案

六个权重，各 10 epoch，`seed=17`，其余字段逐字相同。检测损失取
`box + cls + dfl` 最后 3 epoch 的均值。证据：[`../../results/`](../../results/) 下 `wsweep_*`。

| `w` | 检测损失 | vs `w=0` | `task_ratio` |
|---|---|---|---|
| 0 | 9.6749 | 1.0000 | — |
| 0.25 | 9.6607 | 0.9985 | 0.024 |
| 0.5 | 9.6523 | 0.9977 | 0.050 |
| 1.0 | 9.6963 | 1.0022 | 0.093 |
| 2.0 | 9.6595 | 0.9984 | 0.185 |
| 4.0 | 9.6684 | 0.9993 | 0.376 |

**没有任何权重劣化检测损失，含最大值。** 这命中预注册的边界情况 ①（「向上扩展扫描点」）。

但预注册的敏感性检查同时否定了这个读数：容差在 **1%–5%** 全区间内变动，
选中的 `w` 恒为 4.0；六个点的散布只有 **0.46%**，不到容差的四分之一，且随 `w` **非单调**
（0.5 最低、1.0 最高）。按 §5.5.2 的语义这同时命中边界情况 ③（噪声主导）。

> 另需记录一项预注册前提未被满足：§5.5.2 要求容差大于同种子运行噪声，
> 但六次运行全部 `seed=17`、无重复，噪声从未被估计过。

## 3. 一个更强的信号：KD 项自己也没有被优化

如果 KD 有实际优化压力，**它自己的目标会下降**。这条检验只用已有数据：

| `w` | `relational_raw` ep1–3 | ep8–10 | 降幅 |
|---|---|---|---|
| 0.25 | 0.3457 | 0.3377 | 2.3% |
| 0.5 | 0.3432 | 0.3482 | **−1.4%**（上升） |
| 1.0 | 0.3331 | 0.3231 | 3.0% |
| 2.0 | 0.3423 | 0.3211 | 6.2% |
| 4.0 | 0.3347 | 0.3262 | 2.5% |

**权重提高 16 倍，KD 目标的降幅从 2.3% 变成 2.5%，且非单调。**
在 `w=4.0`、KD 占损失**数值** 37.6% 时，优化器依然没有在最小化它。

一个 16 倍加权都推不动的项，是优化器实际上忽略的项。这说明问题不在「扫描范围不够大」，
而在**度量本身**。

## 4. 探针 A：改用梯度比

### 4.1 为什么换度量

`foundation_task_ratio` 是**损失数值**的比。但参数是沿**梯度**移动的，
损失值大不等于梯度大。要知道 KD 的实际影响力，就得直接量梯度。

梯度比不需要训练即可测量，且**完全不读取 mAP**，
因此 §5.5.1「准则不涉及 mAP」这一可信度前提得以保留。

### 4.2 做法

同一个 batch 上做两次反传——一次只对 KD 项，一次只对检测项——
分别取共享参数上的梯度范数，再解

```
w* = target_ratio × ‖g_task‖ / ‖g_kd‖
```

`target_ratio` 先于测量写定为 **0.1**，即让 KD 梯度范数约为任务梯度范数的一成。

两个梯度反正都要算，于是顺便记录它们的**夹角**。

命令：`python experiments/d2/scripts/kd_gradient_probe.py --mode ratio`

### 4.3 前导结果（2026-08-29，RTX 3090）

证据：[`../../results/probe_a_gradient_ratio.json`](../../results/probe_a_gradient_ratio.json)

```
‖g_kd‖ (w=1) = 135.93       ‖g_task‖ = 5298.80
梯度比        = 0.02565      w* (10% 目标) = 3.90
```

各权重对应的梯度份额：

| `w` | KD 占任务梯度 |
|---|---|
| 0.05（P0 继承值） | **0.13%** |
| 0.25 | 0.64% |
| 1.0 | 2.57% |
| 2.0 | 5.13% |
| **4.0** | **10.26%** |

这个 coco128 前导探针给出两条结论：

1. **继承的 `0.05` 确实形同未开**——只有 0.13% 的梯度份额。
2. **`task_ratio` 作为影响力代理不成立。** 在 `w=1` 时它给出 0.0941，
   而梯度比是 0.0257——**高估 3.67 倍**。
   因此正式标定改用梯度比，`task_ratio` 只保留为辅助记录项。

### 4.4 最终 VOC 四格标定

正式 P1 使用与训练一致的 VOC 配方，在 RTX 3090 上为 A/B/C/D 各测量 50 batches。机器可读证据见 [`../../results/probe_a_voc_3090/`](../../results/probe_a_voc_3090/)。

| 配方 | 教师与层级 | `w=1` 时聚合梯度比 | 10% 目标权重 | cosine 均值（95% CI） | 冲突 batch |
|---|---|---:|---:|---|---:|
| A | DINOv3 P4 | 0.02992 | 3.34277 | +0.0122 [-0.0350, +0.0593] | 44% |
| B | DINOv3 P3+P4+P5 | 0.03332 | 3.00161 | +0.0118 [-0.0385, +0.0620] | 50% |
| C | SigLIP2 P4 | 0.03215 | 3.11066 | -0.0137 [-0.0572, +0.0298] | 52% |
| D | SigLIP2 P3+P4+P5 | 0.05381 | 1.85823 | -0.0014 [-0.0459, +0.0430] | 50% |

四格 cosine 区间都包含 0，没有检测到系统性的同向或反向关系。不同配方的未加权梯度尺度不同，所以正式配置使用不同权重。D 完成了 Probe A 和权重标定，但没有运行 400-epoch 精度实验。

### 4.5 一处口径歧义，必须声明

梯度比有两种算法，两者不等：

| 口径 | 值 | 对应 `w*` |
|---|---|---|
| 均值之比 `‖ḡ_kd‖/‖ḡ_task‖`（本文采用） | 0.02565 | **3.90** |
| 逐 batch 比值再取均值 | 0.03368 | 2.97 |

差 31%，`w*` 差 24%。这是 Jensen 不等式的常规现象，两种口径都说得通——
关心**累积**影响用前者，关心**单步典型**影响用后者。

本文采用前者并如实记录后者。考虑到 `target_ratio = 0.1` 本身就是人为选定（§7.1），
这 24% 的差别不改变任何结论，但**不应当被静默掉**。

另需记录：逐 batch 的梯度比散布很大，范围 **0.0114 – 0.0813**（相差 7 倍），
变异系数 57%。`w*` 是一个平均意义上的量，不是每一步都成立的量。

## 5. 方向关系：扫描失败的真正原因

探针 A 同时记录了两个梯度的夹角，逐 batch 保存（`per_batch_cosines`）。

| 量 | 值 |
|---|---|
| 均值 | −0.0095 |
| 标准差 | **0.1194**（均值绝对值的 13 倍） |
| 均值 95% 置信区间 | **[−0.0509, +0.0319]，包含 0** |
| `t = 均值/标准误` | −0.45 |
| 逐 batch 范围 | −0.272 … +0.292 |
| 内积为负的 batch | 17/32，与抛硬币无区别（双侧 p = 0.86） |
| 分布形状 | 偏度 +0.02、峰度 2.91，接近正态 |

**必须区分两个说法，它们不是一回事：**

| 说法 | 是否成立 |
|---|---|
| 「每个 batch 都近乎正交」 | **不成立**——41% 的 batch 满足 \|cos\| > 0.10，极值达 ±0.29 |
| 「**不存在可检测的系统性对齐**」 | **成立**——均值与 0 无统计区别（t = −0.45） |

> **`−0.0095` 这个负号没有意义**，不要读成「KD 略微对抗检测」。置信区间跨过 0，
> 它和 0、和 +0.03 都无法区分。同理，`grad_conflict_fraction = 0.53` 也**不是一条结果**——
> 17/32 与 50/50 的双侧 p 值是 0.86。

### 5.1 为什么这解释了 §2

§5.5.1 的准则是「取不使检测损失劣化的最大 `w`」，而

> **一阶近似下，与任务梯度正交的更新不改变任务损失。**

判据读的是最后 3 个 epoch 的检测损失**均值**，即几百步累积的量。
逐 batch ±0.12 的涨落在累积中互相抵消，而系统性分量在本样本量下**测不出来**——
因此不存在持续、单向的检测损失劣化。

于是无论 `w` 多大，检测损失都不劣化，准则必然选到扫描上界，必然命中边界情况 ①。

> **该准则不是分辨率不够，而是在不存在系统性对齐时结构上无法给出答案。**
> 它检验的是「KD 会不会伤害检测」，而答案恒为「测不出伤害」，与 `w` 的取值无关。
> **向上扩展扫描点永远得不到结论。**

### 5.2 这个论证的边界

以上只排除了**一阶**效应。方差没有被排除：

逐 batch 夹角散布 ±0.12，意味着 KD 向更新中**注入噪声**——
这是二阶效应（影响更新的方差而非均值），上述论证完全没有覆盖。

在 `w = 4.0` 时它显然不严重（六个权重的检测损失只差 0.46%）。
但噪声注入大致随 `w` 线性放大，**这构成一条反对把 `w` 大幅调高的实在理由**，
而该代价不会体现在任何一阶分析里。

另外，32 个 batch 只能把系统性分量约束到 ±0.05 的量级，**不能证明它是零**。
按点估计外推 320 步（10 epoch），累积项与随机游走项量级相当，
方向则完全取决于那个测不准的均值符号。**「正负抵消、净效应为零」是过度解读。**

## 6. 探针 B：这个目标学得会吗

### 6.1 为什么必须先问这个

探针 A 给出了 KD 信号的**强度**和**方向**，但没回答目标是否**可达**。
若学生根本无法匹配教师的 Gram 结构，P1 测的就是「一个学不进去的信号有没有用」——注定白跑。

### 6.2 做法

把检测损失**完全关掉**（只反传 KD 项），从同一组初始权重跑两个臂：

| 臂 | 可训练 |
|---|---|
| `full` | projector + backbone |
| `projector_only` | **冻结 backbone**，只有 projector |

两个问题用两把不同的尺子量，因为它们的答案不同：

- **可达吗？** 看**拟合 batch**。目标若在「模型可以什么都不干只管拟合」时都推不动，就是硬墙。
- **需要 backbone 吗？** 只看**留出 batch**。在拟合集上，一个可训练的 projector
  几乎能把任何单个 batch 压下去，两个臂都会饱和，比较不出信息。

命令：`python experiments/d2/scripts/kd_gradient_probe.py --mode learnable`

### 6.3 结果

证据：[`../../results/probe_b_learnability.json`](../../results/probe_b_learnability.json)
（Adam lr=1e-3，300 步，2 个拟合 batch，8 个留出 batch）

| 臂 | 可训练张量 | 拟合集降幅 | **留出集**降幅 | 留出残差 |
|---|---|---|---|---|
| `full` | 765 | 94.4% | **59.4%** | 0.1412 |
| `projector_only` | 3 | 42.4% | 28.1% | 0.2500 |

**判定：LEARNABLE**（冻结 backbone 后留出残差为 `full` 的 1.77 倍，高于预设的 1.5 倍门槛）。

1. **目标可达且能泛化。** 留出集降 59.4%，不是记忆效应。
   §3 观察到的「16 倍加权推不动」是权重与预算问题，不是容量或对齐的硬墙。
2. **backbone 确实在参与。** 留出增益中 **53%** 来自 backbone（3 个张量对 765 个张量）。
3. **但投影器吸收并非不存在。** 一个 3 张量的线性投影器单独就拿到了留出增益的将近一半。

> **判定裕度需如实声明：** 1.77 对 1.5，过线但不宽裕，且 1.5 是作者设定、非推导所得。
> 应读比值本身，不要只读标签。

## 7. 结论

| 问题 | 答案 |
|---|---|
| §5.5 准则为何选不出 `w` | 无可检测的系统性对齐 ⇒ 任何权重都不劣化检测损失，准则结构上无解（§5） |
| `w` 取多少 | VOC 四格分别使用 A `3.34277`、B `3.00161`、C `3.11066`、D `1.85823`（§4.4） |
| KD 目标学得进去吗 | 能，留出集降 59.4%，backbone 贡献 53%（§6.3） |
| 是否只是投影器把戏 | 不是，但投影器单独也能拿到近一半增益 |
| 基础模型特征能否改善 mAP | P1 未证明稳定提升；A 只有方向性信号，B no-go，C 一致小幅下降 |

正式 P1 已按 §4.4 的四格标定值锁定配置；A/B/C 完成训练，D 只完成探针。

### 7.1 方向关系对 P1 意味着什么

「无系统性对齐」**排除**了一种坏情况：KD 不是在持续地把模型往检测变差的方向拽。
但它**不预示**会涨点——它与「有用的正则」和「无害的噪声」两种情况都相容，
梯度几何分不出这两者。

> **无系统性对齐是「辅助目标能带来新东西」的必要条件，不是充分条件。**
> 同向意味着没有新信息，反向意味着有害，只有近乎正交时才*可能*带来检测学不到的东西。

由此得到一条**必须在 P1 开跑前写定的预期**：

> **既然不存在系统性对齐，P1 期间检测训练损失同样不会有明显变化。**
> 效应（若存在）只会出现在 mAP 上。
> **不要把「训练损失没变」读作「蒸馏没起作用」。**

`target_ratio = 0.1` 是**人为选定**的，不是测量结果（§4.2）。
每个配方的 `w*` 都与目标比例严格成正比；前导 coco128 探针的换算系数为 38.98，最终 VOC 四格则使用各自的实测换算系数。因此探针 A 提供的是**换算关系**，目标份额取多少仍由人定。
若 P1 得到接近判读线的空结果，「份额目标可能取小了」应排在归因清单靠前的位置。

### 7.2 不阻塞 P1 但需在报告中声明

1. `w*` 测于**训练起点**（未预训练模型），梯度平衡会随训练漂移。
   锁定前若有余力应在训练中期（如 epoch 3 与 9）复测。
2. 探针 A 的**任务侧包含 MoE 辅助损失**（P0 实测为 KD 的 26 倍），
   与 §5.5.2「检测损失不含 `mixture_aux`」的定义不一致。改用不含 aux 的任务梯度会使 `w*` 变小。
3. 探针 B 只优化 KD 项、用 Adam(1e-3)；P1 用 SGD(lr0=0.01) 且 KD 只占约 10% 份额。
   **「原理上可达」不等于「在 P1 的预算下可达」**，这是本次外推最大的缺口。
4. 前导 Probe A 和 Probe B 使用 coco128；最终权重改由 VOC 四格探针确定，每格 50 batches。所有 Probe A 都测于未预训练模型的训练起点，不能证明这一梯度比例在训练中保持不变。

## 8. 附：各损失形式的梯度尺度

`--mode kd` 的离线测量，B=4、C=256、16×16 网格（= wsweep 实参）。
**用高斯随机特征测得**，度量的是各损失形式的**归约结构**，不是真实特征分布下的绝对值；
用途是排序与量级，不是标定值本身。

| `foundation_loss` | ‖∂L/∂student‖ | 相对 relational |
|---|---|---|
| `relational`（当前） | 2.44e-04 | 1.0× |
| `cosine` | 1.96e-03 | 8.0× |
| `l2` | 5.52e-03 | 22.7× |

`relational` 的梯度还随 token 对数被稀释：

| `foundation_relation_samples` | ‖∂L/∂student‖ |
|---|---|
| 16 | 3.80e-03 |
| 64 | 9.70e-04 |
| **256（当前默认）** | **2.44e-04** |

两者都是配置项，不需要改代码，可作为未来独立消融的备选。

## 9. 本文没有主张什么

- **没有用探针主张基础模型特征能改善 mAP。** 探针只标定优化强度；精度结论来自正式 P1 对照。
- **没有移动精度判读线。** 梯度标定不读取 mAP，正式 P1 仍使用预先固定的 0.3 mAP 判读线。
- **没有主张四格权重是最优值。** 它们只是「KD 达到任务梯度 10%」这一预设目标的解。
