# tests

Every test and verification script in one place. Nothing here ships in the bundles.

| script | platform | what it checks |
|---|---|---|
| `run_tests.sh` | Linux x64 / Jetson | 18-test CLI robustness battery (sources, backends, metadata, slicing, CW-NMS, label export, output collisions). `BIN=... ONNX=... ./tests/run_tests.sh` overrides the defaults. |
| `validate_mixture.py` | Linux | v26.08 mixture harness (MoA / MoT / MoLoRA): raw eager-vs-ORT parity, CLI-boxes-in-decode match, feature smoke, MNN parity when a sibling `.mnn` exists. Run from the repo root. |
| `mnn_parity.py` | Linux | standalone MNN-vs-ONNX raw tensor parity + latency for a single model. |
| `coreml_parity_mac.py` | macOS | CoreML parity for the mixture `.mlpackage` exports; ships inside `coreml-mixture-kit.tar.gz` with precomputed inputs and references. |
| `test_quantize_ncnn_int8.py` | Linux (no ncnn needed) | unit test for `scripts/quantize_ncnn_int8.py`'s structural exclusion builder against the real `.param` files: the 36 router-window layers of `moa-n`/`molora-merged`, the p03 six-name sensitive set (== the diff of the two prior-art tables), esmoe/seg stem, DFL, head and SK-gate sets, table stripping, and a `--dry-run`. Plain `python tests/test_quantize_ncnn_int8.py` (84 assertions). |
| `../scripts/quantize_ncnn_int8.py` | Linux x64 (needs `third_party/ncnn-x86-20260526`, built by `scripts/build_ncnn_x86.sh`) | produces a mixed per-layer INT8 ncnn model dir `<name>-int8_ncnn` (conv trunk int8; stem pair, DFL, router windows, SK gates and optionally the head kept float): 1024 even-spread TRAIN images pre-rendered as letterboxed PNGs -> `ncnn2table` (`--method kl\|aciq`; ACIQ preserved detections where KL clipped them on p03) -> table strip -> `ncnn2int8` -> hard post-checks (coverage set equality, no `8=` on non-quantizable types, bin ratio) -> `metadata.yaml` (`precision: int8` + `quant:` provenance) + `quant_manifest.json`. Then certify with `certify_ncnn_int8.py`. |
| `../cpp/tools/ncnn_bench` (+ `../scripts/make_probe_f32.py`, `../jetson/26_ncnn_int8_bench.sh`) | arm64 device / Jetson (x86 = load smoke only) | kernel-only ncnn latency per `(variant, threads)`: fp32 / fp16 / int8+fp32 / int8+fp16 on the same model dir (int8 via the `-int8_ncnn` sibling), interleaved rounds with warmup, median-of-medians / min-median / p90, crude det count + checksum -> `valid`, CPU caps (`asimdhp`, `sdot`, `i8mm`) printed once; fp16 is labelled `fp16(inert)` where the CPU has no fp16 kernels and skipped on router-emulated models. Build: `cmake -S cpp/tools -B cpp/tools/build-x86 -DNCNN_INSTALL=third_party/ncnn-x86-20260526` (Android: NDK toolchain, see the CMakeLists header). One `[ncnn_bench] ...` line per config. Speed verdicts come only from an arm64 device. |
| `certify_ncnn_int8.py` | Linux x64 (accuracy only) | mixed-INT8 ncnn accuracy gate: runs `yolomaster_edge` on `--fp32 <dir>` and `--int8 <dir>` at val settings, scores both with `scripts/eval_map.py::evaluate`, checks the int8 `ep=` really says int8, det-count ratio (warn), conf-0.25 box match >= 0.90 (hard) and `mAP50-95(int8) >= fp32 - 0.010` (hard); prints one markdown row and writes `results/int8_cert/<name>.json`. Exit 0 = PASS. Interpreter `/root/anaconda3/envs/yolo_master/bin/python`. The x86 ms/img column is not a speed result. |
| `../scripts/eval_map.py` | Linux | scores a `--save-txt` dump (`class conf x1 y1 x2 y2`) against YOLO-format labels with ultralytics DetMetrics (comparable to `.val()`); VisDrone names by default, `--names-yaml <metadata.yaml\|dataset.yaml>` for anything else, `--limit N` for a sorted-prefix subset. `evaluate()` is importable (used by `certify_ncnn_int8.py`). |
| `../android/runtime/src/androidTest/.../SegRawTest.kt` | arm64 device (instrumented) | the Android app-shape runtime contract on the staged `v0.1-seg-n_ncnn`: `forwardRaw` + `RawOutput.decode(0.25, 0.45)` == `infer()` box for box (1e-3) on CPU and Vulkan (GPU det count within +/-1 of CPU when a device exists), `maskOverlay(maxSide = 640)` non-null, premultiplied and with non-zero-alpha pixels (plus the `reuse` bitmap path), the direct-RGBA `forwardRaw(ByteBuffer, ...)` == the Bitmap path (and 90-degree rotation swaps `origW/origH`), and `setPowersave(2)` + `threads = 2` leaves the detections unchanged. `gradle :runtime:connectedAndroidTest` (see `android/README.md`); alongside `ParityTest` (precision policy) and `LatencyBenchTest` (per-thread latency rows). |
| `../scripts/quantize_onnx_qnn.py` | Linux x64 (`/data/tmp/venv-v2608`: onnx 1.22, onnxruntime 1.28) | static QDQ quantization of a `models/<name>_ncnn/model.onnx` for the ONNX Runtime QNN (Hexagon HTP) provider: `qnn_preprocess_model` -> calibration over `--n` letterboxed PNGs of `calib/ncnn_*_1024_640` (RGB/255 NCHW, the runtime's normalisation) -> `get_qnn_qdq_config` (`--scheme a16w8`: u16 activations + per-channel int8 weights, the HTP's accuracy mode; `a8w8`: u8 activations, the fast attempt; `--method minmax\|percentile\|entropy`) -> `<dir>/model-<scheme>.onnx` with `ym_quant` + `ym_calib` metadata. Post-check on the CPU EP: out0 max-abs / scaled diff and the conf-0.25 det count vs the float graph on the bench probe (`--det-tol`, dead-graph guard only). `--dump-preds <dir> --images <jpgs> --limit N` runs any of the siblings on the CPU EP at val settings and writes the `class conf x1 y1 x2 y2` txts `eval_map.py` scores (desktop float-vs-quant mAP delta before the phone). |
| `../android/runtime/src/androidTest/.../OrtDumpTest.kt` (+ `../results/int8_bench/device/run_s26_dump.sh`, `../scripts/score_device_dumps.sh`) | arm64 device (instrumented) + pod | the NPU mAP certification dump: for every staged model dir with a `model.onnx`, rows (ncnn, CPU), (ONNX, CPU), (ONNX, NPU fp16) and (ONNX, NPU, INT8 = the staged `model-a16w8.onnx` / `-a8w8`) run the smoke set from `getExternalFilesDir("smoke")` (`smoke_visdrone/` for aerial models) at conf 0.001 / IoU 0.7 / maxDet 300 and write `class conf x1 y1 x2 y2` txts (original pixels) under `files/dump/<model>/<runtime>-<unit>-<precision>/`; one `YM_DUMP model= runtime= unit= precision= backend= placement= images= dets= median_ms=` line per row (`adb logcat -s OrtDumpTest`); rows with no images / no QNN / no QDQ sibling are Assume-skipped. `run_s26_dump.sh <smoke jpgs> [visdrone jpgs] [label]` installs the test APK, pushes the images, runs the class and pulls `../<label>_dump/`; `score_device_dumps.sh <dump> <images> <labels> [--only esmoe]` prints one `eval_map.py --limit 200` line per row. Gate: every NPU row within 1.0 pt mAP50-95 of the same model's CPU rows. |
| `verify_eval_map_cuda.sh` | Linux + CUDA | `eval_map.py` on the C++ CUDA runner's predictions vs `ultralytics val` references (EsMoE-N VisDrone). |
| `tri_backend_map_parity.py` | Linux | 50-image mAP parity across PyTorch / ONNX-sim / ncnn for EsMoE-N VisDrone; also restores ONNX metadata after simplification. |

The last two carry absolute paths into `/data/YOLO-Master` research checkpoints; they are
temporary single-purpose verifiers kept for reproducibility, not portable suites.
