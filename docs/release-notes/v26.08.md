# YOLO-Master v26.08

**Release date:** 2026-08-08
**Release tag:** `YOLO-Master-v26.08`
**Python package identity:** `ultralytics==8.4.101` (upstream baseline; not a separate `26.08` PyPI package)
**Upstream base:** Ultralytics 8.4.101 / YOLO26
**Previous release:** YOLO-Master-v26.02

> v26.08 is a cumulative source release that rebases YOLO-Master on Ultralytics 8.4.101 and hardens the mixture, PEFT, multi-task, export, and Agent runtime paths. The `YOLO-Master-v26.08` tag identifies the exact release commit. The release status below describes implementation and validation scope; it is not an accuracy or hardware-performance claim.

## Release Summary

- Native YOLO26 task, checkpoint, parser, and export contracts are preserved for detect, segment, semantic segment, pose, OBB, classify, and YOLOE profiles.
- MoE, MoA, MoT, MoLoRA, and Latent Mixture use a shared routing protocol for auxiliary losses, temperature scheduling, diagnostics, and export capability disclosure.
- MultiTask training and validation now have explicit task contracts, deterministic multi-source sampling, resumable sampler state, and partial-label loss masks. The shipped release profile is COCO-aligned detect/segment/pose.
- Export preflight reports sparse versus dense execution strategy and refuses contradictory capability declarations before export.
- DDP checkpoint lifecycle, EMA synchronization, AMP-safe sparse dispatch, MPS numerical paths, and NaN recovery received release-gate hardening.

## Highlights

### Architecture at a glance

The release integrates four routed model surfaces plus an independent PEFT adapter surface rather than replacing the upstream model graph:

| Layer | Profile family | Routed object | Boundary |
|---|---|---|---|
| Backbone | ES-MoE, gated MoE, Shared Expert MoE | Conv/FFN expert weights | Eager sparse dispatch or model-scoped expert reuse, depending on the YAML profile. |
| Neck | MoA | Local/regional/global attention paths | Soft mixture by default; optional sparse skipping is batch-level and opt-in. |
| Neck | MoT | Spatial-token transformer experts | Separate from `TaskRouter`, which handles task affinity in MultiTask heads. |
| Head fusion | Latent Mixture | Image-level latent expert probabilities | Dense training; optional sparse eager inference, with calibration enforced only when `require_inference_calibration=True`; declared dense export fallback. |
| PEFT | MoLoRA | Low-rank adapter experts | Runtime injection around selected layers; standard LoRA and enabled MoLoRA are mutually exclusive. |

The control flow is:

```text
YAML → parse_model/mixture_registry → Backbone → Neck → Latent fusion → task heads
PEFT config → Planner/V-PEFT → MoLoRA injection
all routed modules → routing_protocol → CompositeCriterion → Trainer/EMA/DDP/checkpoint
all routed modules → export_preflight → declared dense fallback or refusal
```

Two semantic boundaries are important for users: MoT supplies shared visual features; `TaskRouter` computes per-token affinity and applies task/shared feature gating to every enabled branch, but neither router chooses a final task output. The model YAML and dataset contract determine which branches are built and supervised. Latent Mixture defaults to `value_fusion_mode="router_only"`, so auxiliary inputs influence routing but are not automatically fused as expert values. Use `weighted_sum` explicitly when value fusion is desired.

The architecture analysis is implementation evidence, not an accuracy, convergence, NCCL, or universal hardware-latency claim.

For the complete source-level walkthrough, see the repository's [YOLO-Master Deep Architecture Analysis](https://github.com/Tencent/YOLO-Master/blob/YOLO-Master-v26.08/YOLO-Master-Deep-Analysis.md). The report is a design and code-trace companion to these release notes; the validation and support boundaries in this page remain authoritative for v26.08.

### Unified routing contracts

`ultralytics/nn/modules/routing_protocol.py` is the facade used by MoE, MoA, MoT, MoLoRA, and Latent Mixture modules. It deduplicates auxiliary-loss collection, exposes stable routing diagnostics, keeps rank-local and reduced metrics distinct, and preserves detached diagnostic semantics. Temperature schedules and checkpoint metadata use the same contract.

### MultiTask training hardening

The MultiTask path adds `MultiTaskBatchSampler` with round-robin or weighted task sampling when `task_sources` are configured. Its serializable state is stored with the training checkpoint so a resumed run keeps deterministic task proportions. Missing supervision is represented by validity masks, and only valid task labels contribute to `MultiTaskLoss`. The shipped `yolo26-master-mt-n.yaml` plus `coco-multitask-unified.yaml` path has aligned detection, instance-segmentation, and human-pose labels. Additional head branches require matching data, criteria, and validation contracts; MultiTask OBB is deliberately rejected until that full path exists.

### Latent Mixture configuration and export safety

Latent models now expose named configuration for value fusion, router initialization, temperature, and inference `top-k`. Parser construction and checkpoints retain this metadata. Sparse eager inference is available under the documented eval/top-k/tracing gates; projects that set `require_inference_calibration=True` must pass the dense-vs-sparse calibration check before dispatch. Unsupported export backends select an explicitly declared dense fallback or fail during preflight.

### PEFT and MoLoRA compatibility

MoLoRA fallback adapters support round-trip save/load and routing-aware merge contracts. Standard LoRA remains available, while the PEFT Planner, V-PEFT solvers, LOVO validation API, and FewShot-LoRA controls remain explicit opt-in paths. A positive standard `lora_r` and `molora_num_experts > 0` cannot be combined.

## P0-P2 Hardening

| Priority | Area | Release-level correction |
|---|---|---|
| P0 | Routing and losses | One routing facade; auxiliary losses are collected once, normalized by family, budgeted, and isolated when non-finite. |
| P0 | Checkpoint/EMA/DDP | Checkpoint bootstrap and pre-epoch coordination are deterministic; EMA buffers and PEFT scaling state stay synchronized. |
| P0 | Export contracts | Preflight validates module/backend declarations and records sparse or dense strategy, fallback, and performance caveat metadata. |
| P1 | MultiTask data | Deterministic round-robin/weighted sampling, resumable sampler state, and partial-label masks prevent silent task imbalance or false negatives. |
| P1 | AMP/MPS numerical paths | Sparse accumulation aligns dtypes; MPS bilinear sampling uses the native-safe path; NaN recovery is synchronized across ranks. |
| P1 | Latent Mixture | Named configuration and checkpoint metadata prevent parser/config drift; sparse inference can be calibration-gated explicitly before dispatch. |
| P2 | PEFT and diagnostics | MoLoRA fallback round trips, routing snapshots, and validator metrics expose stable contracts for debugging and integration. |

## Compatibility and Migration

There are no formally declared breaking changes for the documented public APIs. The main migration is the upstream rebase from Ultralytics 8.3.240 to 8.4.101.

1. Install the editable checkout and confirm the resolved import path:

   ```bash
   pip install -e .
   python -c "import ultralytics; print(ultralytics.__version__, ultralytics.__file__)"
   yolo version
   yolo checks
   ```

2. Keep official YOLO26 YAML files unchanged when you need the native baseline. Mixture profiles are additive files under `ultralytics/cfg/models/`.
3. Retest integrations that import Ultralytics internals directly against the 8.4.101 parser, trainer, task-head, checkpoint, and exporter contracts.
4. Use `task="multitask"` with a dataset YAML that declares non-empty `tasks`, includes `detect`, and uses the supported COCO multi-task format. Start with `ultralytics/cfg/datasets/coco-multitask-unified.yaml` for the shipped detect/segment/pose profile.
5. Enable MoLoRA only with `molora_num_experts > 0`; do not pass a positive standard `lora_r` in the same training request.

## Known Limitations

- No real CUDA/MPS AMP multi-epoch result is recorded in this release audit.
- No real NCCL two-GPU training result is recorded; DDP evidence is lifecycle and contract focused.
- No TensorRT hardware latency or memory benchmark is available for routed profiles.
- Core ML validation is environment-blocked by the current macOS `coremltools`/SciPy binary loading issue.
- The repository-wide Ruff report still contains historical findings outside the touched release surface, principally in `agent/`, `scripts/`, and legacy helpers.
- MultiTask prediction currently uses the detection predictor; a public `tasks=[...]` multi-output prediction API is not part of v26.08.
- MoA, MoT, MoLoRA, Latent Mixture, and FewShot-LoRA profiles do not ship release-level accuracy or latency tables without matching evaluated artifacts.
