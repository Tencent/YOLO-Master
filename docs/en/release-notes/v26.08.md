## Architecture boundaries

- MoT supplies shared visual features. `TaskRouter` computes per-token task affinity and gates features for every enabled task branch; neither router selects one final task output.
- The model YAML and dataset contract decide which MultiTask branches are built and supervised. The shipped profile is detect/segment/pose; additional branch types require their own complete data, loss, and validation contracts.
- Latent Mixture defaults to `value_fusion_mode="router_only"`; use `weighted_sum` only when input feature values should be explicitly fused.
- Eager sparse routing and exported execution are different contracts. ONNX-style tracing uses the declared dense fallback unless a backend explicitly preserves routing.

!!! warning "Evidence scope"

    The release evidence covers focused build, forward, serialization, export, and contract checks. It does not establish full-dataset convergence, multi-node NCCL stability, or universal hardware latency.
